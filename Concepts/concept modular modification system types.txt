_individual flag-based modification
e.g. every ability has a hardcoded check for every other possibly interfering ability being present
con: lots of duplicity and extra code

_central registered temporary event-based modification
abilities call multiple teirs of defined(hardcoded?) centralised events with temporary modifiers when needed
abilities register their own functions to run on these centralised events
calling ability chooses event payload and called abilities rule required payloads to run
con: lots of event calls and refreshes and necessity for each ability to register correct events every change

_local registered perpetual pointer-based modification
abilities have public stat modifiers and call empty named events
each stat is made up of its name and the privately set final value and multiple modifiers
the modifiers are lists in which pointers to other stats and the source can be entered
the modifiers are always summed and applied to the stat value
abilities register modifiers by name on ruled abilities on every change
con: abilities need to refresh all modifiers every change or reliably add and remove

_central collection-based modification
abilities have privately set stats and call centralised empty named events
modifiers are bundled with application requirements and source and added to a centralised collection
ability stats browse central collection for applicable modifiers and temporarily apply them when read
con: requires extensive modifier rule system and frequent collection browsing

_central collection-based modification extension
stats have lists with pointers to modifications referencing them to signal changes
abilities locally save rule applicable modifiers when new abilities are added
stats browse local modifier collection to calculate a cached value (need to check for new mods meanwhile!)
when a locally saved modifier value changes or it is removed affected stats are recalculated
(source removed can either be done by killswitch or checked by hosting ability regularly for reliability)
con: requires extensive modifier rule system and optimised rule filtered collection browsing
// calculations are dependent on mods being applied in an order which could end up recursive

// turns out event based is probably already the way to go :/

_example
ability deals fire damage
ability has keywords attack, fire
mod makes fire attacks deal additional ice damage
mod makes fire attacks get ice keyword
mod converts all elemental damage to ice damage
mod converts all elemental keywords to ice keyword
